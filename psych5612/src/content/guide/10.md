## Why an FSM is not enough for every problem

A fixed FSM has a finite number of states and therefore a fixed finite capacity to distinguish histories. Some tasks on inputs of arbitrary length require retaining more intermediate information than that fixed state set can encode. Adding indefinitely extendable external storage changes the abstract model.

A Turing machine has a finite control, a read/write head, and a tape divided into cells containing symbols from a finite alphabet, including blank. The tape provides unbounded potential storage. A machine table specifies what happens for each current state and scanned symbol: write a symbol, move the head, and enter the next state, or halt. The controller remains finite even though the whole machine's possible tape configurations are unbounded.

## How the operator interacts with it

For an FSM, the operator supplies input symbols/values over successive time steps and receives output symbols/values as the machine operates. State carries finite history from one step to the next. It is not normally a “write an arbitrarily long question, then wait for the final tape” arrangement.

For a TM, the operator encodes an input word on the tape, positions the head in the specified initial arrangement, and starts the machine. The controller then performs its rule-driven sequence. If the machine halts, the operator reads the answer from the tape using the output convention. For some inputs it may never halt, in which case there is no completed output in this computational sense.

The word “unbounded” is an idealization: any particular completed computation uses finitely much tape, but the model imposes no fixed overall maximum across all possible inputs. A real computer has finite resources. A mechanical demonstration is a finite realization of part of the model, not literally an infinite tape.

**Practice TM:** input is a unary number represented by n copies of 1 followed by blank. In state SCAN, on 1 keep 1 and move right; on blank write 1 and halt. The example's main lesson is the link among formal rule, step sequence, coding convention, and mathematical function.

## Implementing a mathematical function

For Q15's function F on natural numbers, M implements F if, for each x, starting M with the specified encoding of x causes it to halt with the encoding of F(x) as its output. If F is total, this must work for every input in the stipulated domain. In the more general theory of partial functions, nonhalting inputs correspond to inputs on which the computed function is undefined.

Do not substitute “M usually gives a plausible answer.” A mathematical definition quantifies over the specified inputs and specifies halting and exact output.

## Functional equivalence

> Two machines M1 and M2 are functionally equivalent if and only if they halt on exactly the same input words and, for every input on which they halt, produce the same output word. Both conditions matter. If one halts on an input while the other does not, they are not equivalent, even if they agree on every input both happen to finish.

They may use different states, representations of intermediate work, head movements, and numbers of steps. Functional equivalence does not imply physical identity, identical internal trajectories, or equal speed. “They can solve similar kinds of tasks” is too vague.

## Universal Turing machines

> A UTM is a TM that, given an encoded description of any target TM M and an input x for M, simulates M on x. For each fixed valid description of M, the UTM's resulting input-output behavior is functionally equivalent to M: it halts exactly when M halts and gives the same result, under the encoding convention.

Its input has two parts: software, the description of the target machine's table/program; and data, the input word for that target. The same physical controller can behave like different target machines because the description is stored and interpreted as data. Universality is a property shared by an entire class of machines, not the name of one unique physical device.

Haugeland's simulation explanation uses an emulator that tracks a simulated machine's current state, tape contents, and head position, finds the matching rule, and updates that representation. This clarifies why simulation can require many physical steps for one simulated step while preserving the computed function.

## Hardware and software routes

Given a machine table, one route builds dedicated hardware implementing the specified control. Another encodes it as instructions for a universal machine. Both can implement the same abstract computation. This is the significance of a stored program: sufficiently general hardware can acquire new computational behavior through new instructions rather than a new circuit for every task.

## Von Neumann architecture

A von Neumann machine has a processor/control organization and addressable memory storing instructions and data. Relative to a basic TM, practical machines have multiple registers, direct addressing of memory, and richer primitive operations such as addition, increment, branch, and jump. The TM's head reaches cells by moving along a tape. A VNM can perform in one machine operation something requiring many elementary TM steps.

For the idealized unbounded models, the class of VNM-computable functions equals the class of Turing-computable functions. Equality of computable-function classes is not equality of time, hardware, or resource limits. The course's mathematical equivalence assumes the appropriate idealization, not a claim that a fixed finite laptop contains unlimited storage.

## Third important fact about computation

> Technologies exist for the industrial production of physical devices that implement universal programmable computers within bounded engineering parameters: clock frequency f, power consumption W, failure rate epsilon, mass m, cost C, and so on. Multiple realizations of an abstract computational system/virtual machine are routine. [L09, p. 29.]

The three facts progress from finite input-output mapping, to finite state and history, to programmable universality. They establish that computation can be physically implemented. They do not, by themselves, establish that every implementation understands or is conscious.
